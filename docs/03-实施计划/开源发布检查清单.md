# 开源发布检查清单

> 配套流程：[开源开发、发版与 CI/CD 完整流程](发版与CI-CD完整流程.md)。
>
> 本文件只负责发布门禁和打勾，不重复解释完整原理。
>
> 基线：pre-release 0.3.4，2026-07-27。

## 一、首次开源一次性检查

### 公开基线

- [ ] 当前私有发布分支已经完成分批提交和详细合并。
- [ ] 工作区干净，没有遗漏的未提交源码。
- [ ] 已记录首次公开导出所对应的私有 commit。
- [ ] 后端、前端、Docker 和 migration 验收通过。
- [ ] 当前私有仓库不会直接设置为公开。

### 临时导出

- [ ] 只把 `scripts/export-public-source.sh` 指向新建的临时 staging。
- [ ] 没有把导出目标设置为已有 Git 仓库。
- [ ] staging 不包含 `.git/`、`.env`、data、uploads、日志和构建产物。
- [ ] staging 不包含 `AGENTS.md`、`CLAUDE.md`、内部审查、排障和个人决策文档。
- [ ] staging 不包含 Korea、生产域名、SSH 配置和本机绝对路径。

### 法律与内容

- [ ] 已由项目所有者确定许可证。
- [ ] 根目录包含完整 `LICENSE`。
- [ ] README 明确项目仍为 alpha/pre-release。
- [ ] `SECURITY.md` 提供非公开漏洞报告方式。
- [ ] `CONTRIBUTING.md` 说明环境、测试和 PR 规则。
- [ ] 默认提示词、图片、字体、图标和其他素材的来源允许公开。
- [ ] 来源或授权不清楚的第三方内容已经重写、替换或排除。
- [ ] 第三方依赖许可证没有已知冲突。

### 泄密扫描

- [ ] 已执行路径和环境变量文件扫描。
- [ ] 已执行凭据正则扫描。
- [ ] 已使用 Gitleaks 扫描 staging。
- [ ] 所有扫描命中都已逐条人工判断。
- [ ] 测试中的模拟密钥不能真实使用。
- [ ] 公开仓库创建后又对其完整历史执行了一次 Gitleaks。

参考命令：

```bash
find . -name '.env*' -o -name '*.env' -o -name '.DS_Store'

rg -n --hidden \
  --glob '!.git/**' \
  --glob '!package-lock.json' \
  '/Users/|/home/|korea|BEGIN (RSA |OPENSSH |EC )?PRIVATE KEY|Authorization: Bearer|sk-[A-Za-z0-9]{12,}'

gitleaks dir .
```

### 公开仓库

- [ ] 使用 staging 创建全新的 Git 历史。
- [ ] 公开仓库没有继承当前私有仓库的历史提交。
- [ ] 公开 `main` 已启用分支保护。
- [ ] 合并前要求核心 CI 通过。
- [ ] 已配置 Issue、PR 模板和安全报告入口。
- [ ] 已建立明确的 `private`、`public` 远程。

## 二、每次版本发布

### Git 与版本

- [ ] 目标 tag 对应公开 `main` 上的已合并 commit。
- [ ] 发布 commit 的工作区干净。
- [ ] 版本号符合 SemVer。
- [ ] 应用显示版本与 Git tag 一致。
- [ ] tag 尚未存在，不覆盖或移动旧 tag。
- [ ] 发布说明列出新增、修复、已知问题、迁移和回滚方式。

### 自动化测试

- [ ] `cd backend && go test ./...`
- [ ] `cd backend && go vet ./...`
- [ ] `cd frontend && npm ci`
- [ ] `cd frontend && npm run lint`
- [ ] `cd frontend && npm run test -- --run`
- [ ] `cd frontend && npm run build`
- [ ] `git diff --check`
- [ ] 示例环境变量可以渲染 Compose。
- [ ] 空白 PostgreSQL 可以执行全部生产 migration。
- [ ] 已有测试库可以重复启动且不会重放 migration。
- [ ] 关键浏览器链路通过。

### 公开内容

- [ ] 本版本没有新增真实环境变量文件。
- [ ] 本版本没有新增 data、上传文件、日志和测试报告。
- [ ] 本版本没有新增内部路径、域名和服务器信息。
- [ ] 本版本新增文档属于公开用户需要的内容。
- [ ] 本版本新增素材和提示词具备公开边界。

### 镜像

- [ ] Git tag 已触发 release workflow。
- [ ] backend 镜像构建成功。
- [ ] web 镜像构建成功。
- [ ] extractor 镜像构建成功。
- [ ] migrate 镜像构建成功。
- [ ] `linux/amd64` 和 `linux/arm64` manifest 均存在。
- [ ] 镜像版本和 build ref 可追溯到 tag。
- [ ] 镜像已生成 SBOM 和 provenance。
- [ ] 预发布版本没有更新 `latest`。
- [ ] 镜像 digest 已记录到发布说明或私有部署记录。

## 三、本地部署门禁

- [ ] 使用与发布 tag 相同的镜像。
- [ ] `.env.docker` 未被覆盖或修改。
- [ ] data 目录未被删除、替换或上传。
- [ ] migrate 成功后才启动新 backend。
- [ ] 所有容器 healthy。
- [ ] `/health` 返回目标版本、build ref 和 schema。
- [ ] 登录、会话读取、发送和文件入口冒烟通过。
- [ ] 上一版本镜像仍可用于回滚。

## 四、Korea 部署门禁

- [ ] 部署动作来自私有流程，并经过人工批准。
- [ ] 已记录当前版本、目标版本和上一可回滚版本。
- [ ] 已记录当前 schema 和目标 migration。
- [ ] 已确认服务器磁盘空间和容器状态。
- [ ] 没有 rsync `.env.docker`。
- [ ] 没有 rsync data、uploads 或数据库目录。
- [ ] 没有执行 `docker compose down -v`。
- [ ] 没有使用 Watchtower 或无人值守自动升级。
- [ ] `docker compose pull` 拉到目标镜像 digest。
- [ ] migrate 成功。
- [ ] 新容器全部 healthy。
- [ ] 公网 `/health` 与目标版本一致。
- [ ] 公网登录页、API、SSE 和一次基础对话冒烟通过。
- [ ] 部署结果已写入私有记录。

## 五、回滚门禁

- [ ] 发布前已经明确应用回滚是否兼容新 schema。
- [ ] 不可逆 migration 已有备份或向前修复方案。
- [ ] 上一版本镜像 tag/digest 仍存在。
- [ ] 回滚不会恢复旧 `.env.docker` 覆盖当前配置。
- [ ] 回滚不会删除或替换 data。
- [ ] 回滚后 `/health`、登录、会话和新 run 已验证。

## 六、外部贡献同步

- [ ] 外部 PR 的 CI 全部通过。
- [ ] PR 不依赖维护者生产环境。
- [ ] PR 不新增未经授权的素材或提示词。
- [ ] 合并后已同步到本地 `main`。
- [ ] 合并后已推送到私有远程。
- [ ] 在制 `release/*` 已合入最新公开 `main`。
- [ ] 贡献者 authorship 得到保留。

## 七、发布结论

只有以下信息都能明确回答，版本才可以发布：

```text
公开 commit：
版本 tag：
schema：
镜像 digest：
CI 结果：
本地 Docker 结果：
Korea 部署结果：
上一回滚版本：
已知问题：
```

任一项未知时，结论填写“阻塞”，不得用“应该没问题”代替验证。

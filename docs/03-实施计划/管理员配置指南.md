# 管理员配置指南

适用版本：pre-release 0.3.4

本项目的业务运行时配置都在管理员后台完成。`.env.docker` 只放数据库、JWT、端口、存储路径、Python extractor 内部地址等基础设施配置；模型渠道、API key、搜索和网页提取服务不写进 env。

## 首次进入

1. 启动 Docker Compose。
2. 注册第一个用户。首个注册用户会自动成为管理员。
3. 打开右上角用户菜单，进入管理后台。

## 模型与渠道

1. 在“模型与服务”里打开“模型”。
2. 左侧选择或新建渠道。
3. 渠道设置只需要填：渠道名、协议、Base URL、API key、启用状态。
4. 保存渠道后，在右侧检测连接或拉取模型。
5. 点击“模型管理”后添加或编辑模型。

模型编辑只暴露模型本身的参数：模型 ID、显示名、上下文、最大输出、模型排序、最低可见组、能力和 thinking。联网方式不在模型里配置，聊天侧只保留“联网：开启/关闭”，系统按可用联网服务和模型能力自适应。

## 会话记忆容量

“系统配置”中的 `memory_max_chars` 控制单个会话记忆卡的字符硬上限。模型维护时需要返回完整 JSON 和整张固定 section 记忆卡，因此所需输出能力高于字符档位本身：

| 记忆字符上限 | 最低模型输出上限 |
| ---: | ---: |
| 4,000 | 8,192 token |
| 8,000 | 12,288 token |
| 12,000 | 16,384 token |
| 16,000 | 20,480 token |

记忆维护复用当前会话模型与渠道，但使用独立输出预算并关闭可选 thinking。若模型已声明的最大输出低于所选档位，自动维护不会调用 provider，手动“整理/重试”会返回明确的能力不足提示，现有记忆保持不变。若 provider 实际达到输出上限，系统同样拒绝保存不完整或被迫缩短的结果。管理员应降低记忆档位，或为该会话选择最大输出更高的模型。

## 联网服务

“渠道与联网服务”中展示两条独立、可排序的运行链和一条 OCR 配置：

- 搜索：Tavily、Brave Search、Exa、博查、SearXNG。
- 网页提取：Firecrawl、Jina Reader、Tavily Extract、Exa Extract 按管理员顺序执行，内置 Basic 是最后本地兜底。
- 文档 OCR：`MinerU 精准解析`

颜色含义：

- 绿色：配置完整且启用。
- 红色：缺配置或未配置。
- 灰色：已停用。
- 管理员列表中的外部服务顺序由上到下决定，拖拽落下即原子保存；第一个取得有效正文的服务会停止链路，空结果或失败才继续，全部外部服务未取得正文后才执行 Basic。网页提取默认总 deadline 为 30 秒，并对当前剩余链路采用 `4:2:1` 的递减权重分配：靠前服务获得更充足的完成窗口，快速失败后剩余时间自动交给后备服务。

配置规则：

- Tavily 搜索与 Tavily Extract、Exa 搜索与 Exa Extract 是两条独立配置，不共享 Key 或启停状态。
- SearXNG 和 Jina Reader 的 Key 可选；其余云服务通常需要对应 Key。编辑弹窗可对未保存草稿做最小真实请求测试，测试不会落库、不会记配额，也不会回显 Key 或正文。
- Basic 是内置 SSRF 防护提取器，不入库、不能编辑、不能停用，始终追加在管理员排序的外部服务之后。
- Basic 只输出清理后的普通正文和必要换行。短正文直接返回；长正文才按 goal/标题选择相关段落并尝试可选小模型提炼，小模型不可用时仍返回本地选出的原文片段。`detail=source` 不经过模型改写。
- 所有提取目标先做 URL 安全预检；Basic 额外执行受限 DNS 与拨号防护。
- 启用 MinerU 后，PDF 会先进入可恢复后台 OCR，不在上传请求里等待解析完成。
- MinerU 精准解析需要 Token，默认 Base URL 为 `https://mineru.net`，可配置最大并发。Token 不回显；留空保存时会保留已保存 Token。
- 单文件上传上限由部署变量 `PY_EXTRACTOR_MAX_UPLOAD_BYTES` 统一决定（默认 25 MiB），web、backend 与本地 extractor 使用同一硬顶；管理员的“单文件大小”只能在此硬顶以内设置。MinerU 精准解析的 200 MB/200 页仅是已进入异步 OCR 后的上游限制，不代表 EffChat 会接收 200 MB 上传。
- 系统不会保留结果 zip 或 JSON。OCR 原始 PDF 在成功前受管暂存，最长 24 小时；成功写入 sidecar 后立即删除。OCR 未完成前不能发送消息，但可以删除或在失败后重试。

## 用户组限额

用户组是当前版本的唯一配额入口，不做商业计费和套餐。`0` 表示不限额。

可配置项：

- 每日消息数。
- 每日模型 token 近似上限。
- 并发 run 上限。
- 每日工具调用次数。
- 每日搜索次数。
- 每日网页提取次数。
- 每日 OCR 文件数。
- 每日 OCR 页数。

“用量”页会展示今日治理概览、用户接近限额的压力、模型消耗、工具用量和 OCR 文件/页数。工具结果体量是近似估算，只用于防滥用观察。

历史统计可选择今天、7 天、30 天，或使用两个原生日期输入查询自定义范围。自定义范围按浏览器本地日期生成右开区间，最长 90 天，不能包含未来日期。切换历史范围只改变模型、运行、工具和用户聚合；“今日用户组限额”始终按当天计算。

## 工具

工具页只治理现有工具，不包含 Shell、浏览器自动化或代码执行器。可配置工具启停和超时；网页提取的新默认超时为 30 秒。工具错误会以结构化形式显示在对话中。

主模型遇到尚未输出任何内容的瞬时网关或网络故障（例如 `502/503/504`）时，系统会以带随机抖动的短退避自动重试一次；鉴权/参数错误、用户停止和已产生内容后的中断不会重试。每次尝试仍分别进入模型用量记录，后端日志以 `[model_retry]` 标记自动重试轨迹。

## 字体

字体页分三层：

1. 顶部一行上传字体文件和显示名称。
2. 中部设置中文字体、英文字体、代码字体三个槽位。
3. 下部查看字体列表、启停或删除。

删除正在使用的字体会提示对应槽位将恢复系统默认。

## 文件清理

系统配置的“文件”区域提供“清理遗留文件”按钮。默认清理 24 小时前的未发送附件，以及删除会话后已保留 24 小时的附件，并同步删除受管理的磁盘文件；仍在可见会话消息中引用的附件不会被清理。删除会话后若 OCR 仍在运行，清理会等待任务结束或失败，避免迟到结果重新写入文件；同一操作还会清理超期、未被租约认领的 OCR 原件并返回 OCR 清理计数。

仍在可见会话消息中引用，或仍绑定在活跃会话文件区的文件不会被该按钮清理。

## 实例状态

系统分组的“实例状态”页用于核对当前部署容器：应用版本、build ref、数据库 schema、启动时间、Go 运行时、容器内存、受管存储容量、PostgreSQL 和文档提取器健康。

- 页面只在进入时和点击刷新时读取，不持续轮询。
- PostgreSQL 或提取器单项失败时，其余状态仍可查看。
- 容器运行时无法读取 cgroup 时，内存项显示不可用；这不代表服务故障。
- 该页不是宿主机、Docker 平台或 NewAPI 监控，不提供日志、环境变量、服务地址、密钥、绝对路径、备份或模型体检。
